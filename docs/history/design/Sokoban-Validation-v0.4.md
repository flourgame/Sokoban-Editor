# 单关卡验证、完整求解过程与回放

版本：0.4.0；日期：2026-10-05；对应 FR-009、FR-017、FR-022。

## 使用方式

1. 在 `editor` 场景的 Play Mode 打开或编辑关卡，点击右侧“验证”。验证使用当前页签的内存布局，因此无需先保存。
2. 有解时，左侧显示独立回放棋盘，右侧列出完整步骤、推箱数、移动数、搜索节点和耗时。
3. “播放”自动执行全部步骤，可暂停并切换慢速/正常/快速；“上一步”“下一步”逐格前后查看，通关后仍可回退。
4. “回到起点”重置回放；“复制完整过程”复制全部步骤、每一步的玩家/箱子坐标、完整方向串及统计，与当前播放进度无关。
5. 空格播放/暂停，←/→ 单步，Home 回到起点，Esc 返回编辑。返回编辑不改变源关卡布局。
6. 求解结果写入当前页签的 `solution` 元数据并显示脏标记；点击编辑器“写入”后保存到 JSON。修改关卡会清除旧求解结果，需重新验证。

结构错误显示具体修正提示；无解显示已证明的死点/无匹配或搜索穷尽信息。默认限时 30 秒、扩展 100000 节点、发现 200000 状态；超时/达到上限仅表示未确定，不表示无解。关闭面板、返回场景或退出 Play Mode 会取消正在运行的求解。

## 实现

- `Assets/game_script/SokobanSolver.cs`：不引用 Unity 的求解内核、快照/选项/进度/结果。后台任务持有自己的数据副本。
- `Assets/game_script/SokobanSolutionPlayback.cs`：主线程快照适配、逐步解答记录、回放/回退/重置和完整过程输出。回放前用游戏的 `SokobanSimulation` 完整验证解答。
- `Assets/level_editor/SokobanEditorSolver.cs`：验证模态面板、后台任务轮询、结果和步骤显示、播放控制。步骤文本分块显示，避免 Legacy Text 单网格顶点数量限制。
- `Assets/Tests/Editor/SokobanSolverChecks.cs`：可重复执行的 Editor-only 回归检查，不进入玩家构建。通过 MCP `execute_code` 执行 `return SokobanSolverChecks.Run();`。

算法按推箱扩展状态，每次 BFS 找到玩家到站位的最短行走路线。边包含完整走路序列和一次推动。A* 使用反向推箱距离和 Hungarian 最小箱子/目标匹配作为推箱数下界；无法匹配与 2×2 冻结布局被剪枝。

目标按 `(推箱数, 移动数)` 比较。状态键保留玩家实际位置和排序箱子位置；仅以玩家可达区域合并状态会失去次级最少移动保证，因此未采用该合并。队列优先级为 `(累计推箱 + 推箱下界, 累计移动)`。同一状态发现更优代价时可重新进入队列；旧队列项被跳过。

解答为标准 LURD：`u/d/l/r` 是走路，`U/D/L/R` 是推箱。所有移动都计入步数。已完成的初始布局返回 0 推、0 步。

## 成熟项目参考

调研了 [SokoSolve](https://github.com/guylangston/SokoSolve) 的公开仓库信息（C#，GPL-2.0）及 [JSoko](https://jsokoapplet.sourceforge.io/) 的公开介绍。当前求解器为本项目独立实现，没有复制这些项目的源代码，也未添加其库或运行依赖。采用的推箱状态搜索、反向距离、死锁剪枝和二分图最小匹配均为通用算法。

## 验证记录

Unity 2022.3.51f1c1 编译成功；Play Mode 验证后 Console 无脚本错误或警告。

- 基础规则：单次推箱、包含走路的完整路径、多个箱子、静态死锁、无围墙地图的行边界、初始零步通关。
- 回放：完整前进至通关、通关后回退、逐步退回起点、重置、计数与坐标恢复、源关卡不被修改、完整报告包含每一步。
- 输入和边界：箱/目标数量不一致、空实体、玩家/箱子重叠、重复目标、无效快照、超时、节点/状态上限、开始前和搜索中取消。
- 长路径：40×3 走廊的 36 次推动/36 步完整解答与回放。
- 最优性：60 个固定种子随机小关卡，与独立逐步移动的穷举 Dijkstra 比较可解性、最少推箱数和次级最少步数；全部一致。
- 实际界面：通过 Play Mode 的真实 Button 回调验证上一步、下一步、完成后回退、重置、完整过程复制、自动播放至通关、重新播放/暂停、无解、结构错误及零步通关；额外验证 36 步完整列表的三个文本块及通关后回退、取消后立即返回编辑。截图为 `Assets/Screenshots/solver-replay.png`。
