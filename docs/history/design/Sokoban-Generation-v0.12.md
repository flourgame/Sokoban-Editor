# 增量式关卡生成改进与验证

日期：2026-10-06。项目版本：0.12.1。生成器：`incremental-search-2.1`。环境：Unity 2022.3.51f1c1 / Windows。

0.12.1增加可留空的箱子数量与内部墙比例：默认留空自动决定，填写数值时沿用精确约束。单关和批量共用参数读取、校验、生成与评分，后续策略改动默认同时适用于两者。

## 1. 改进目的与来源

旧生成器每次独立构造随机地形，从完成布局反向拉箱，再返回第一个满足要求的结果。候选失败后无法利用此前的可解结构，也没有在合格结果之间比较布局质量。此次将主流程改为“从可解小布局开始，逐步修改，求解确认，失败回退，多起点探索，合格后继续择优”。反向拉箱保留为补充起点。

主要参考仓库：[huanggaole/AutoGenerateSokobanLevel](https://github.com/huanggaole/AutoGenerateSokobanLevel)，阅读版本固定为提交 [`4ccf418633cf47e153436723c45518ea60f8cfa9`](https://github.com/huanggaole/AutoGenerateSokobanLevel/tree/4ccf418633cf47e153436723c45518ea60f8cfa9)。具体借鉴关系如下：

| 仓库中的逻辑 | 本项目采用方式 |
| --- | --- |
| [C++ 主循环：增加箱子/目标或墙，求解后 save，失败 load 回退](https://github.com/huanggaole/AutoGenerateSokobanLevel/blob/4ccf418633cf47e153436723c45518ea60f8cfa9/AutoGenerateSokobanLevel/AutoGenerateSokobanLevel.cpp#L61) | 在独立副本上执行小幅修改；通过求解的布局成为下一轮父候选，失败直接丢弃副本 |
| [JavaScript 加权放置](https://github.com/huanggaole/AutoGenerateSokobanLevel/blob/4ccf418633cf47e153436723c45518ea60f8cfa9/HTML_Sokoban/js/GenerateLevel.js#L94) | 按墙邻接、实体邻近、可推动位置和目标反向距离进行加权抽样；权重依据项目需求重新设计 |
| [JavaScript 质量评估与最佳候选保留](https://github.com/huanggaole/AutoGenerateSokobanLevel/blob/4ccf418633cf47e153436723c45518ea60f8cfa9/HTML_Sokoban/js/AILevelGenerator.js#L274) | 找到匹配关卡后继续搜索，在严格合格候选中按独立布局质量择优 |

候选池、多起点重启、修改动作成功率反馈、缓存、严格参数约束及质量公式属于本项目补充。实现为独立纯 C# 代码，没有复制仓库源文件，也没有引入其求解器。所查提交未见明确的 LICENSE 文件；来源标注用于说明算法借鉴关系，不表示获得复制该仓库代码的许可。

论文《Generation of Sokoban Stages using Recurrent Neural Networks》的学习式生成路线保留为后续研究方向。本次采用仓库的增量生成思路，不引入模型训练或训练数据依赖。

## 2. 当前生成流程

1. 校验并复制输入参数，以种子初始化随机数。沿用地图尺寸、箱子数、步数区间、难度、内部墙比例、候选数及时间预算。
2. 建立起点：通常从带外围墙的空房间开始，加入首对箱子和目标；每第三次构造起点改用原反向拉箱方法。起点也必须通过结构检查与真实求解。
3. 从最多 **8 个**已验证可解候选中选取父布局。80% 的选择来自排名前三，20% 在整个池中抽样。
4. 深复制父布局，执行一种修改：增加箱子/目标对、增加或交换墙、移动箱子、移动目标、移动两格连续墙段、移动玩家；箱数自动时可删除箱子/目标对（至少保留一对），墙比例自动时可删除内部墙。无连续墙段时尝试单墙交换；所有改动只发生在副本上。
5. 执行低成本检查：地面连通、实体合法且不重叠、箱子与目标数量相等、箱子出生不在目标上、箱子到目标的静态反向距离可达。通过后才调用现有求解器。
6. 求解失败丢弃修改，保留父布局。确认无解的布局加入无解缓存；求解成功的布局缓存并参与候选池筛选。超时、搜索上限等未知结果不会缓存为无解。
7. 所有可解布局先用不探查替代解的复杂度评估进行中间排名；箱子数、墙数和步数均达到输出条件时，再进行完整复杂度评估与替代解探查。修改权重随步数/难度偏差和动作成功率调整。
8. 每逢第 **12** 次尝试，或连续 **28** 次未改善时，重新构造起点；原候选池继续保留。候选池满时主要替换末位，另有10%机会保留较弱的探索分支，首位不受该分支替换影响。
9. 首次找到完全合格结果后，最多再进行 **24** 次尝试，从合格结果中返回质量最高者；质量相同则比较复杂度分数。候选上限或时间预算可以提前结束此窗口。

默认参数为8×8、箱数自动、20–60步、普通难度、墙比例自动、200次尝试、60秒总预算、单候选求解2秒。求解同时限制50000个展开节点和100000个发现状态；完整复杂度评估预算最多1500毫秒，并受剩余总时间约束。

自动箱数范围为1到`min(8, max(2, floor(内部格数/8)), 可容纳的箱子/目标对数)`；填了墙比例时，从容纳空间中先扣除指定墙数。自动墙数上限为内部格数45%按原规则换算的墙数，并为固定箱数（箱数也自动时至少一对）及玩家预留地面；每个实际布局还必须满足`地面数 >= 2×箱数+1`。默认8×8的自动箱数上限为4。简单/普通/困难分别软偏好1/2/3箱（受上限约束），自动墙数软偏好20%换算值；这些偏好只用于搜索引导，不是输出的硬条件。反向起点在偏好箱数附近抽样，自动墙比例在10–30%抽样并按可用空间减少。

## 3. 中间搜索与输出约束

中间候选可以暂时少箱子、少墙，或处于其他步数与难度区间，只要已确认可解，就可作为后续修改的基础。排名优先考虑箱子数、墙数、步数和难度距目标的差距，再结合布局质量与池内差异；中间排名不等于最终输出分数。

输出必须同时满足：指定尺寸、箱子/目标等量、箱数和墙数在内部合法范围、填写箱数时准确匹配、填写墙比例时按换算墙数准确匹配、连通地面、初始箱子不占目标、求解成功、总移动在指定区间、完整复杂度评估后的难度档位相符，以及不在调用方提供的排除布局集合中。两项可独立自动，墙比例的0是有效精确值。绝不因为预算不足自动放宽填写的参数。

内部墙数按内部格数乘墙比例，使用四舍五入（中点远离零）得到。求解目标仍是**先最少推箱，再在相同推箱数中最少总移动**；总移动包含推箱动作，不能解释为无推箱优先级的全局最短路径。

总时间用尽时，若已有完全合格且完成验证的候选，返回保存的最佳结果；否则返回超时。用户显式取消始终返回取消，不交付候选。相同版本、参数和种子在未受时间限制影响时可复现；触及求解、复杂度探查或总时间上限时，机器速度及调度可能影响结果。

## 4. 难度与布局质量

难度口径保持：箱子依赖35%、腾挪/规划30%、空间争用20%、失败分支15%；低于25为简单，25–低于50为普通，50及以上为困难。完整评估探查至多12个替代推法，找到更简单有效解时降低复杂度，未知分支不计为死路。

新增质量评估器版本为 `layout-quality-1.0`，独立于难度，用于合格候选择优：

`布局质量 = 100 × (0.60 × 地面使用率 + 0.25 × 墙体结构 + 0.15 × 箱子互动)`

| 项 | 定义 |
| --- | --- |
| 地面使用率 | 初始玩家/箱子占用格及完整解答中玩家/箱子访问格的去重数量，除以内部地面数 |
| 墙体结构 | 至少有一个四邻接墙格的内部墙数，除以内部墙总数；邻接可以是外围墙；无内部墙时为1 |
| 箱子互动 | 现有复杂度报告的依赖、规划、空间三项归一化分数的平均值 |

同步记录已用地面和未用地面数。步数、推箱数不作为额外独立质量奖励，以免为了加分制造长距离空走。

该分数衡量特定解答和部分结构特征，不能证明空白区必然无用、墙体结构必然优良、推箱顺序必需、唯一解或玩家体验更好。六组固定样本的提升只能作为此次实现的技术对照；质量与难度仍需人工试玩和玩家数据校准。
