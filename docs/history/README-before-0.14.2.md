# 推箱子 · Unity 游戏与关卡工作台

一个可以从主菜单选关、游玩、撤销、重开、通关并继续下一关的推箱子游戏，同时提供可在独立运行版本中使用的关卡编辑器。编辑器包含完整求解回放、按复杂度生成关卡、分类管理、批量生成、批量验证和可保存的印章画笔。

当前版本：**0.14.1**。开发环境为 **Unity 2022.3.51f1c1 / Windows**。棋盘（墙/地板/目标/箱子/玩家）使用 `Assets/Resources/img` 下的贴图预制体，界面外壳与弹窗烘焙在 `game.unity` 中可直接在 Scene 视图调整；其余界面配色仍为统一主题色。

> 历史版本已完成 Windows 构建；0.13.0验证范围为 Unity 编译、模型、生成表单与原版HTML算法对照，本轮不构建、不打包，未重新进行独立 Play 界面回归。交付状态、测试覆盖及仍需补齐的产品内容见 验收与缺项清单（原阶段附件未随附）。目前正式内置流程为 3 关；工作区还包含自建关卡和草稿，不应将草稿数量视为正式关卡数量。

## 快速运行

1. 在 Unity Hub 中添加此工程，使用 Unity **2022.3.51f1c1** 打开。
2. 首次打开需要解析 `Packages` 中的 Unity 依赖。其他 Unity 2022.3 LTS 版本尚不能视为已验证兼容。
3. 打开 `Assets/Scenes/start.unity`，点击 Play。
4. 选择「开始游戏」，选中已解锁关卡后点击开始。进入关卡工作台：按 `=`，点击右上角「GM ▼」展开，再选择「关卡编辑器」。

构建 Windows 版本需要安装对应 Unity 的 Windows Build Support。Build Settings 已包含并按顺序启用 `start`、`level`、`game`、`editor` 四个场景；将 `start` 保持为第一个场景。

游戏运行不需要 MCP 服务器。工程中的 MCP 包用于开发期间操作 Unity；源码准备脚本会在提交副本中移除该开发依赖。

## 玩家体验

- 主菜单 → 选关与预览 → 游戏 → 通关结算 → 下一关；最后一关回到选关。
- 墙体阻挡、单箱推动、多个箱子与目标点、全部入位通关；非法移动不增加步数。
- 移动数、推箱数、用时；撤销、重开、暂停、返回选关。
- 主菜单和暂停菜单提供「设置」：音乐/音效音量滑条与动画开关。目前为可操作占位界面，仅保留本次运行的数值，不应用音频或动画效果，不写入存档。
- 默认选关只显示 BuiltIn 来源关卡，名称与详情不显示类别；新玩家从第一关开始，正常通关解锁下一关。
- 本地保存解锁进度、完成状态及最佳成绩，选关页显示锁定和完成标记。改名保留成绩，修改布局后重新记录。
- 编辑试玩、GM 游玩和强制完成不计普通成绩，也不推进玩家解锁。
- 14×10 以内固定显示整图；超过任一尺寸时跟随玩家，并限制视野不越出地图。可随时打开完整地图。
- 非法草稿及已确认无解的关卡不能进入普通游玩；加载失败提供可读提示和返回入口。

## 关卡编辑器

编辑器采用三栏布局与多页签工作区，可以关闭所有页签；空编辑区提供新增关卡入口。

- 绘制玩家、箱子、墙体、目标和地面，支持目标点与实体分层显示。
- 框选、Ctrl 多选、复制、剪切、粘贴、填充、长按移动、撤销。
- 中键平移、Ctrl + 滚轮缩放，修改名称和地图尺寸。
- 「保存」更新当前文档；「保存为关卡」创建独立关卡；保存失败保留文档并显示原因。
- 未保存页签关闭时可保存、丢弃或取消；程序退出时可全部保存、丢弃或取消。
- 程序内切换场景及试玩后返回，保留打开文档、未保存内容、撤销记录及视图；未保存文档不跨程序重启恢复。
- 「日志」展示本次运行的操作与任务过程，支持复制和清空。

推荐创作流程：新增/打开 → 绘制与命名 → 验证结构和可解性 → 回放检查 → 保存 → 试玩 → 返回继续编辑。

### 印章预设画笔

点击顶部「印章」，选择预设并点击「使用印章」。鼠标落点对应最上方一行中最左侧的已绘制格，制作画布的透明边距不影响落位。移动鼠标显示预览，左键可连续放置，右键或 Esc 退出；每次放置可以整体撤销。内置直角墙、箱子与目标、地面区域三份示例。

点击「新建印章」会打开独立制作页签，沿用编辑器笔刷、选区、复制/剪切/粘贴、填充、尺寸调整和撤销；也可「从选区新建」。填写名称并点击「保存印章」，之后可以在印章库重用或继续编辑。

- 尺寸为 1–40，初始未绘制格透明；「透明」笔刷恢复透明格。
- 透明格保留目标内容；明确绘制的地面格会清空原格内容。
- 支持目标与箱子/玩家叠层，最多一个玩家；无需围墙或相等的箱子与目标数。
- 任一绘制格越界时整次拒绝，不部分写入。放置后关卡旧验证步数变为 -1。
- 印章制作不会写入关卡列表；关闭页签及退出仍有未保存保护。

实现与检查记录见 印章系统验收（原阶段附件未随附）。

### 求解与完整回放

使用项目内的纯 C# 求解器：推箱 A*、玩家站位 BFS、反向距离与箱子/目标匹配下界，以及安全死锁剪枝。无需额外下载第三方求解程序。

求解目标是**先最少推箱，再在这些解答中最少总移动**。总移动包含推箱动作，不能将此数值解释为不考虑推箱优先级的全局最短移动数。

结果包括可解/无解/非法/超时/搜索上限/取消、总移动、推箱、搜索节点与耗时。超时和搜索上限表示未确定，不能等同于无解。

回放提供自动播放/暂停、上一步/下一步、回到起点、速度切换与完整流程复制。空格切换播放，左右键单步，Home 回起点，Esc 返回编辑；回放不改变源布局。

### 自动生成与复杂度

填写地图长宽（各5–8）、**推箱次数范围**、生成难度、种子、时间和候选预算；走路不计入范围。难度下拉框提供“不限、简单、普通、困难”，默认普通；不限时保留实际复杂度评估，但不按档位筛选。默认8×8、1–60推、400次候选、60秒。**箱子数量和内部墙比例默认留空，由算法自动决定；填写数值时精确匹配，墙比例填0表示没有内部墙。** 自动箱数最多8个并受实体空间限制；自动墙使用HTML原配置，填写墙比例仍限0–45%。输出展示实际数量。

生成流程按参考仓库HTML版实现：空房间随机玩家 → 按原配置增加墙或箱子/目标 → 按HTML构造求解规则确认 → 成功保存、失败回退 → 保留合格候选。最终由现有Push A*确认最少推箱次数与完整解答，再按原复杂度筛选。种子继续保留；填写的结构、推箱次数和复杂度必须匹配。

**单关自动生成与批量生成共用参数读取、校验、生成策略、难度和质量评估。** 批量仅增加数量、逐关种子、批次内去重与任务调度；后续生成逻辑变更默认同时作用于两者。

沿用HTML质量公式、候选比较和提前结束规则；复杂度与质量分别展示和保存。参考来源为 [huanggaole/AutoGenerateSokobanLevel](https://github.com/huanggaole/AutoGenerateSokobanLevel)，直接核对用户下载的HTML版本，文件内容与固定提交一致。当前算法、项目保留的约束及原版对照见 [HTML生成设计与验证](design/Sokoban-Generation-v0.13.md)。精确结构或高推箱下限可能导致无匹配；失败时不放宽条件。旧JSON中的移动范围保留为历史信息，需要重新填写推箱范围后才能再次生成。

难度独立于长度，按解答中的以下内容估算：

| 指标 | 权重 | 关注内容 |
| --- | --- | --- |
| 箱子依赖 | 35% | 先搬开哪些箱子、阻挡关系及依赖链 |
| 腾挪与规划 | 30% | 临时远离目标、搬离已到位目标、重新处理箱子 |
| 空间争用 | 20% | 多箱共用关键格、推入格相互阻挡 |
| 失败分支 | 15% | 有限探查中已确认无解的替代推动 |

总分低于 25 为简单，25–49.99 为普通，50 及以上为困难。有限探查找到更简单解答时按较低复杂度评估，未确定分支不计为死路。此分数用于筛选，仍需要试玩校准，不能替代真实玩家难度评价。

### 关卡管理与批量任务

- 分类筛选与新增分类；单选、Ctrl、Shift、Ctrl+Shift 多选、全选及方向键选择。
- 批量迁移分类、删除确认、排序、长按拖动调整关卡顺序；删除及失败恢复有备份保护。
- 批量生成数量 1–100，显示整批进度和逐关结果；结果可预览、回放、采用为页签和批量保存，保存不覆盖已有文件。
- 批量验证使用同样的分类与多选方式；显示逐关结果、进度、报告复制和已求解快照回放。
- 两种批量任务可以取消，离开页面或切换场景仍继续；结束后在当前页面底部提醒，可返回结果。任务顺序执行，当前不提供批处理暂停或并行。

## JSON 与保存位置

关卡使用 JSON schema v1。`terrain` 中 `#` 为墙、`.` 为地面；坐标原点在左上，x 向右、y 向下。玩家/箱子/目标均须在地面上，箱子与目标数量必须一致。尺寸范围为 3–40。

顶层 `verifiedMoves` 是可信解关总移动数：**-1 表示未验证，0 表示有效的零步解**。旧文件缺字段按 -1 读取。名称、布局、尺寸、剪贴板操作和撤销等内容修改会清除旧结果；重新验证后填入新的步数。求解元数据用于检查与回放，普通游戏始终按实际箱子状态判定通关。

批量验证处理已保存快照，写回前检查文件是否已变更或删除；发生冲突时保留报告，避免覆盖新的编辑内容。

| 数据 | Unity 编辑器中 | 独立运行版本中 |
| --- | --- | --- |
| 内置与自建关卡 | `Assets/Resources/data/level` | 打包资源作为初始内容，本地关卡优先覆盖 |
| 编辑器保存的关卡及分类/排序 | 同上 | `Application.persistentDataPath/level` |
| 印章预设及自建印章 | `Assets/Resources/data/Stamps/{stampId}.json` | 读取打包预设，自建/改动保存到 `Application.persistentDataPath/Stamps`；本地同 ID 优先 |
| 玩家解锁、完成状态与最佳成绩 | `Application.persistentDataPath/progress.json` | 同左 |

Windows 默认持久目录为 `%USERPROFILE%/AppData/LocalLow/DefaultCompany/kuluobishi`。独立运行时不会向安装目录或包内资源写入。删除打包关卡使用本地删除标记。

## 工程结构

```text
Assets/
  Scenes/             四个流程场景
  game_script/        规则、数据、求解、生成、进度与游戏表现
  level_editor/       运行时编辑器、管理、任务与通知
  Resources/          关卡及字体资源
  Tests/Editor/       可复现模型检查与构建入口
  Tests/              仅开发版本启用的独立运行验收入口
  doc/                SDD 和阶段设计报告
  Screenshots/        开发阶段界面截图
Packages/             Unity 依赖清单及锁文件
ProjectSettings/      项目设置与构建场景
Tools/                源码准备和检查脚本
docs/                 本次验收报告与界面证据
```

规则与求解核心独立于表现层；编辑器依赖游戏核心，游戏通过注册接口创建编辑器场景控制器。

## GitHub 提交

```powershell
./Tools/prepare-source.ps1
```

脚本生成 `SourceSubmission/Sokoban-时间戳`，只保留 `Assets`（含 `.meta`）、`Packages`、`ProjectSettings`、`Tools` 与说明文档，并移除 MCP 开发依赖。不会复制 `Library`、`Temp`、构建程序或用户存档，也不会覆盖已有目录内容。

在该副本中创建 Git 仓库并推送到自己的 GitHub 仓库；用仓库 URL 填写答题栏。**当前工作区尚未关联或发布 GitHub 仓库。** 公开提交前应确认资源授权，并按验收清单在全新克隆环境复测首次导入。
